**F-1 — HARDENING, S3 — Pilot stage table overstates machine replay coverage of the reviewed transcriptions.**

- Evidence: `docs/bridge/DF10_TH3_Pilot.md:7` lists S0 artifacts "PDF digest, page geometry, clause boxes, literal word snapshots, reviewed readings" with result "Replayed against the supplied PDF". The verifier recomputes only the *literal word snapshots* from verified PDF bytes (`src/creib/verify.py:159-174`, `_verify_bbox_span` word-center selection and digest at `:165-174`). The reviewed readings are verified solely by byte-hash, NFC, LF, and final-newline checks (`src/creib/verify.py:842-853` plus `_decode_declared_nfc` at `:339-347`); no code path compares transcription tokens to the snapshot words under `declared_transformations` (`authority/source_anchors.json:55-60, 140-146`).
- Violated claim/invariant: the CR-EIB weakest-link rule (`docs/bridge/CR-EIB-0.1_Bridge_Contract.md:397-399`, "assurance cannot exceed the weakest unre-established step"); the S0 wording implies machine-established textual fidelity for material that is pinned but human-reviewed.
- Exploit/counterexample: a transcription drift (e.g., dropping the `CCPResult` conjunct from `authority/transcriptions/DF-10.reviewed.txt:3`) would be caught only by the reviewed-sha policy pin (`src/creib/verify.py:48, 376-386`), not by any replay against PDF text; the stage row wrongly implies replay-level assurance.
- Smallest repair: split the S0 row into "machine-replayed against the verified PDF" (digest/geometry/snapshots) and "hash-pinned, human-reviewed; transformation fidelity not machine-checked" (reviewed readings).
- Falsifier: point to any executed code that validates a reviewed reading against the snapshot under its declared transformations.
