**Status.** An external audit of this repository at commit `391d8c6` (9 September 2026), supplied by the maintainer as a PDF whose text is reproduced below. Nothing in this file is evidence about any model; the evidence is in the records the register entries cite.

## Where the harness agrees

Every finding was reproduced before it was acted on. The one the audit calls the only issue touching the integrity of a published table is the first.

- **Observations no run record names enter `claims`, and a document said they did not** (finding 1, medium-high). True. `claims` reads a directory by enumeration and tests every observation; `dependence`, `controls`, `cycles`, `compare` and `report` read it through its run records. `docs/document-dependence.md` said all of them pass over the stopped gpt-oss:20b run's 296 observations. Reproduced as the audit states: `claims` over the committed directory tests UDP-01 on 1,731 observations, the table says 1,450, and the difference is the stopped run's observations in scope. The table had been generated on 8 September over a scratch directory holding the five complete runs' records and nothing else, and the document's closing note said it was generated over the committed directory. Three things were done. `claims` now names the observations no supplied run record carries, per run id and count, in its summary (`observations_without_run_record`) and at the head of its Markdown, so a table generated from a directory that holds such observations says so (`tests/test_without_run.py`). The document states the command its table was generated with, `--without-run 3bbf9932aab16166`, corrects both sentences, and says what including the 296 gives: no status moves, and the counts that change are listed in its "Correction of 9 September". `CLAUDE.md` says that a commit of observations before their run record must say so and that a document reading such a directory accounts for them. Register entry H43. The audit's alternative, a warning, is what was built; refusing such observations was not (see below). Every committed records directory was checked with the new accounting, and `semantics-unit-dependence` is the only one that holds observations without a run record.
- **A round-trip request with no recorded reply stopped a re-score where a cycle step degraded** (finding 2). True. Both now become `PREREQUISITE_UNAVAILABLE` under `--replay-dir` with the reason in the record, the record carrying the planned variant, and both still stop a live run; a test covers each side. No committed re-score met the case, since one that had would have stopped without a run record. Register entry H45.
- **The fence rule as stated was stronger than the code** (finding 3). True. A fence's candidates are now the top-level objects inside its body, so a sentence or a language tag other than `json` beside the object no longer drops it to the bare pool; this also covers the audit's remark on the fence regex's language tags, since a fence tagged otherwise still yields the object inside it. Measured on every committed reply before the change was committed: of 12,156 replies with content, none is scored differently, so no record is re-scored. Kernel point P-08 holds the rule beside P-02, P-06 and P-07; register entry H44.
- **The vocabulary rule's justification rested on an uncommitted check** (finding 4). True. The check is now `tests/test_controls_vocabulary_rules.py`: it recomputes every renamed-vocabulary row of the committed controls directories (`semantics-unit-controls`, `ecs-unit-controls`) under the substring rule, a longest-match rule and a word-boundary rule, and refuses a difference. The rule is kept, since nothing recorded distinguishes the three; a future corpus whose vocabulary nests will move the test, and the decision is then made with the record in view. V-01's note says so.
- **The `--without-run` ambiguity arm could skip** (finding 5). True. The arm now runs on two run records whose ids differ in the last character, since the resolution reads nothing but the id.
- **`select_variants` can send more calls than `--limit`** (finding 6). True and kept: a selected variant's baseline is added after the cut because a cut that dropped it would make the selected variant `PREREQUISITE_UNAVAILABLE`, which is worse than an extra call. The option's help text now says so.
- **CI omitted `cite`; the README's count was stale; H40's counts were commit-bound without saying so** (finding 7). All three corrected: CI runs `python tools/check.py cite` after `pilots`; the README gives the battery's count and the tree's; H40 says its counts were measured at `37a471e` and that a later tree holds more. The twelve "published so far" commits stay in the history, which is never rewritten; the publishing rule now says what such a commit must say.

## What was not taken, and why

- **A `LICENSE` file.** A licence is the owner's decision, not the harness's. Noted to the maintainer; nothing added.
- **Refusing observations that no run record names.** Not taken. An observation is one reply, and one reply where a condition holds refutes a claim whether or not the run that made it finished; refusing them would make a stopped run's records unreadable by the one command that reads observations rather than runs. Naming them is what a table needs in order to say what it read, and `--without-run` leaves them out when a document wants the completed runs only.
- **Rewriting the partial-run commits out of the history.** Never: published history is not rewritten (`CLAUDE.md`, Publishing).
- **Changing the substring rule of V-01.** Not taken, for the reason V-01 gives and the test now holds: on every committed controls record the three rules agree, so a change would rest on no record.

## Changes to the machine made in reply, in one place

`claims` reports `observations_without_run_record` (`runs_without_record` in `claims.py`), and its Markdown opens with the same when it is not empty; the ROUND_TRIP branch of the runner degrades under replay as the CYCLE branch does; `recover_json_object` takes a fence's candidates from the top-level objects inside its body (`_top_level_objects`); kernel point P-08 and the regenerated `docs/kernel.md`; `tests/test_controls_vocabulary_rules.py`; the deterministic ambiguity arm in `tests/test_without_run.py`; the `--limit` help text; `cite` in `.github/workflows/ci.yml`. Documents: `docs/document-dependence.md` corrected and its table's command stated; register entries H43 to H45 and the H40 wording; `docs/how-it-works.md`, `agent.md`, `CLAUDE.md`, `README.md`, and this directory's `README.md`. No record was written or changed.
