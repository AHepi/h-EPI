# SMF-0.4 translation qualification fixture

## Status and claim boundary

This document specifies the first non-Popper qualification specimen for the
target translation harness. The Harbor Relay Charter (`HRC-1`) is fictional and
stipulative. It describes no real harbour or practice. Its controller records
say how planted defects were constructed; they are not semantic authority over
CR-1.0, evidence of real-world truth, or proof that a translation is faithful.

The strongest automatic result permitted by this fixture is:

```text
ALL_DECLARED_EXPOSURE_TOKENS_MATCH_CONTROLLER
```

That means only that the frozen report's declared `case_id::exposure_id` token
sets exactly matched the controller declarations. The result itself does not
verify that the observations were generated by executing the mutations. It
does not mean `TRANSLATION_CORRECT`,
`SEMANTICALLY_TRUE`, `CONFIRMED`, or `PROVED_SEMANTICS`. Any escaped required
exposure token blocks the automatic label rather than lowering a score. Passing examples,
test counts, model agreement, and absence of a discovered defect have no
promotional effect.

The fixture manifest retains the earlier boundary string
`ALL_DECLARED_EXPOSURES_REPRODUCED` as legacy fixture metadata. It is not the
runtime qualification-result label.

## Why a synthetic second subject is necessary

CR-1.0 is the project authority, but it cannot serve as a complete harness
oracle: its translation is the object under criticism, and several readings
remain genuinely open. A controller-written fictional source can contain known
omissions, ambiguities, modality changes, hidden imports, and benign variants.
This lets the harness be tested for exact exposure and restraint without
declaring any interpretation of Popper correct.

HRC-1 is structurally unlike a philosophical thesis. It is a small procedural
charter involving events, round-indexed roles, partial order, modal eligibility
and availability, one exception, a non-normative example, and explicitly open
predicates. The shared structural challenges test general translation machinery
rather than Popper-specific vocabulary.

The first fixture uses an exact UTF-8 authority. A later version may add a
deterministically rendered PDF with page-spanning and layout mutations. PDF
evidence is intentionally not simulated here.

## Source-obligation structure

The controller graph contains 17 span-bound obligations. Each records its exact
line bytes, obligation kind, dependencies, facets, and protected distinctions.
The principal challenges are:

| Source surface | Distinction that must remain visible |
|---|---|
| Normative boundary | Numbered rules and footnotes versus headings and example |
| Charter boundary | Procedural closure versus truth, ownership, competence, and undefined incompatibility |
| Opening | Registered material versus an opened round |
| Offer | Record bytes versus round- and event-indexed role |
| Challenge | A full biconditional versus only some necessary conditions |
| Overlap | One carrier with two roles versus identification or disjointness |
| Responses | A response event versus resolution of its target |
| Eligibility | Modal eligibility versus entry, selection, or acceptance |
| Closure | Preconditions versus the explicit closure event |
| Emergency seal | Exceptional closure versus answering a paused challenge |
| Order | Required precedence versus a global total order |
| Availability | Retrievability versus actual inspection, use, or endorsement |
| Open predicates | Use of an input relation versus a definition of that relation |
| Reference | Two live antecedent readings versus a silent choice |
| Example | Illustration versus an induced universal rule |

The controller key names 13 discriminator families and ten protected case
families. These are construction expectations, not expected semantic labels.
A generated question need not copy the controller wording. It must bind the
same obligation, rivals, held-fixed conditions, controlled difference, possible
falsifier, and scope.

## Mutation programme

The mutation ledger contains 31 isolated single mutations and three compound
mutations. Every isolated mutation starts from the same frozen baseline.
Compound runs contain only their declared members; results cannot inherit an
earlier mutation accidentally.

| Surface | Count | Examples of required exposure |
|---|---:|---|
| Source capture | 5 | Authority drift, borrowed anchor, omitted footnote span, changed modal force, undeclared normalization |
| Obligation graph | 3 | Boundary omission, example promotion, filled open predicate |
| Interpretation forest | 1 | Silent deletion of one unresolved antecedent |
| Semantic model | 10 | Context-index loss, forced disjointness, modality collapse, total-order import, distinction collapse |
| Bridge | 1 | A model primitive with neither source image nor typed import |
| Formal extraction | 1 | A theorem using a source-free hidden premise |
| Research routing | 1 | External search for a fictional meaning fixed only by the source and its review |
| Decision boundary | 2 | Model consensus or finite pass count promoted into acceptance |
| Test contract | 1 | Expected result rewritten after observing failure |
| Hardening | 6 | Disconnected repair, protected loss, scope escape, inconsistency, connected finite repair, deletion witness |
| Compound | 3 | Simultaneous source/model/formal, candidate/test, and scope/decision defects |

For an integrity defect, the fixture can require mechanical rejection. For a
semantic change, the minimum exposure is different: the harness must bind the
affected source obligation, display the changed distinction or strength, trace
the consequences, and construct a reviewable discriminator while leaving the
semantic verdict null. The controller does not allow a mutation label to become
an operative human locus assessment automatically.

The compound cases qualify plural criticism. They must allow candidate,
auxiliary, test, and scope criticisms to remain live together. One selected
action may serve several compatible frontier criticisms, but selecting it
cannot delete or rank the others.

## Benign controls

Six controls guard against a detector that treats every change as semantic
damage. They cover independent-clause reordering, example-only names, a heading
rename, a checked definitional abbreviation, an explicit successor-source
clarification, and declared text reflow.

Every byte change still creates new provenance identity. An obligation-graph
isomorphism or semantic equivalence is a separately reviewable proposal; it
does not license silent identity reuse. Conversely, a harmless formal
abbreviation is not hardening, and an explicit HRC-2 clarification cannot
rewrite HRC-1 or erase its historical rival branches.

## Expected dynamic questions

A capable generator should discover questions equivalent in discriminating
structure to these:

1. Does registration without `OPEN` begin a round?
2. Can byte-identical records have different roles under different rounds and
   entry histories?
3. What happens when each challenge conjunct is removed while all others are
   held fixed?
4. Can one record occupy both offer and challenge roles?
5. Can a replacement be eligible without being entered or accepted?
6. Do satisfied preconditions close a round without a `CLOSE` event?
7. Does an emergency seal answer a paused challenge, or only close the round?
8. Can unconstrained concurrent events be exchanged without changing the
   charter result?
9. Can a record be available while never inspected or endorsed?
10. Can rival content-identity, incompatibility, or independence relations both
    expand the same supplied charter structure?
11. Which antecedent does “the record” select, if any?
12. Does changing only the example change a normative consequence?

“Does the source support our model?” is inadmissible: it supplies no rival,
controlled difference, or possible criticism.

## Blind qualification protocol

1. Verify the full manifest and the construction-key commitment.
2. Materialize only the exact paths in `HRC-1.blind-packet.json` for the
   translating system. Record prompts, tools, configurations, and packet bytes.
3. Produce and freeze source capture, obligation graph, rival interpretations,
   neutral semantic model candidate, two-way bridge, loss/addition ledger,
   dynamic questions, round-trip prose, and plural criticism packet.
4. Apply every single mutation independently to the same frozen baseline.
5. Apply the three declared compound mutations.
6. Apply the benign controls.
7. Reveal the controller key and compare exact required exposures. Do not feed
   its expected answers back into the already-frozen translation.
8. Replay in normal and optimized Python modes and compare canonical outputs.
9. Report escaped mutations, false collapses, and unresolved reviews without a
   scalar quality score.
10. A human may then authorize a bounded qualification disposition. Mechanical
    completion alone cannot do so.

A full blind qualification is conjunctive: every named required exposure must
be independently produced, every blind boundary and digest must hold, every
benign control must receive its declared treatment, all dependencies and
alternatives must remain visible, and no prohibited semantic promotion may
occur. The current runner checks the committed fixture and freeze bindings and
compares declared exposure tokens; it does not by itself establish the other
facts in this paragraph.

## Positive hardening plumbing fixture

`HRC-M-H05-CONNECTED-FINITE-REPAIR` is the finite plumbing specification for the
typed hardening resolver. In a deliberately finite, exhaustively enumerated HRC
comparison class, it adds round and entry-event arguments to `OFFER`, removes
the named intrinsic-role expansion, preserves every registered intended case,
and requires typed gain, preservation, non-broadening, non-vacuity, deletion,
and human-decision evidence.

The status contract says that a future executor satisfying the complete
contract may reproduce the scoped workflow status `HARDENING_UNREFUTED`. The
v1 runtime does not: it parses caller-supplied payloads but keeps them
`INCONCLUSIVE` because no artifact resolver or model executor is bound. A future
positive result would qualify resolver plumbing only. It would not establish HRC translation fidelity, generalize beyond
the declared finite class, or bear on Popper. Removing any necessary evidence
must yield `UNRESOLVED`; a known regression, loss, weakening, collapsed
distinction, broadened result, or vacuous successor must yield `NO_HARDENING`.
The production neutral semantic model remains unresolved until it has its own
typed executable semantics and evidence.

## CR-1.0 as a second hostile specimen

The synthetic fixture tests sensitivity because the planted construction is
known. A frozen CR-1.0 candidate tests restraint where the correct translation
is not known.

The initial hostile specimen is bound to:

```text
Authority SHA-256: 08ff81e848fea976b558345402d85723173be8f40f1041fb00d6267f1e026b8b
Repository commit: 0162af9e9f445ceb9f1ec6621331deea8bd49b13
Repository tree:   7ff951d19da6b805a5e9615d06eed3c9f21ccf56
Calibration-record file SHA-256 at that commit:
                   e033cb8e82c6a38799f8b8c8f7f3bf4694ac54046e099e98b17d8abc8fb3d999
Preserved as:      forge/history/invalidated-runs/SMF-CALIBRATION-CR-1-0-001.4219efce.pre-generic-translation-harness.json
```

First produce a fresh bounded translation in a new namespace without exposing
the existing semantic candidate. Compare them only after both are frozen.
Agreement is not validation; disagreement opens a source-bound problem.

Then mutate only the frozen translation candidate, never the authority:

- omit one DF-7a span;
- promote `t0`, `t1`, or `t2` into source-named witnesses;
- turn SC-8's necessary conditions into a definition of `CLine`;
- add a history argument to `PBCrit`;
- collapse availability into occurrence or retention;
- merge the endpoint and resulting problem situation;
- silently select one of the five endpoint readings;
- infer a global time order;
- retarget `EIB-TH3B-PILOT`; or
- promote successful Lean replay into mapping fidelity.

These mutations have known provenance and contract consequences without giving
the harness an oracle for Popper's intended meaning. The required outcome is
restraint: preserve alternatives, expose source-free additions and losses, keep
formal success separate, and stop `UNRESOLVED` awaiting human review.

Human review should be requested in small packets containing the exact source
span, proposed plain-language reading, strongest live alternative, model and
mathematical consequences, and the decision actually needed. The reviewer need
not repair the whole translation in order to qualify the harness boundary.

## Present limitation

This tranche supplies immutable fixture data, independent consistency tests,
and an executable comparison runner. The runner replays the actual candidate
snapshot and canonical record inventory against the candidate freeze, validates
the exposure-report freeze, then compares the report's declared
`case_id::exposure_id` token sets with the controller's declared token sets. It
reports exact matches, misses, and false positives.

The repository does not commit an HRC candidate translation, candidate freeze,
exposure report, or report freeze. The command sequence below therefore needs
operator-supplied candidate artifacts; the committed controller data alone is
not a runnable end-to-end qualification instance.

That comparison does not execute a translation, apply the natural-language
model mutations, generate exposure observations, or verify evidence that a
mutation was actually run. It also cannot prove that the report producer was
blind to the controller before invoking the runner, authenticate a human
reviewer, or award a human qualification disposition. The fixture must remain
useful even if its first translation is poor: exposed failure is the intended
output of a qualification instrument.

## Command-line freeze and comparison

The following sequence is copyable once the candidate records and exposure
report have been prepared. Output paths are no-clobber: choose paths that do not
already exist.

```sh
PYTHONPATH=src python tools/run_translation_qualification.py freeze-snapshot \
  --records-dir /path/to/translation-records \
  --snapshot /path/to/translation-snapshot.json \
  --output /path/to/candidate-snapshot.freeze.json
```

Copy the resulting `freeze_id` into the exposure report's
`candidate_snapshot_freeze_id`, then freeze that report before controller
comparison:

```sh
PYTHONPATH=src python tools/run_translation_qualification.py freeze-report \
  --report /path/to/HRC-1.exposure-report.json \
  --output /path/to/HRC-1.exposure-report.freeze.json

PYTHONPATH=src python tools/run_translation_qualification.py qualify-report \
  --report /path/to/HRC-1.exposure-report.json \
  --freeze /path/to/HRC-1.exposure-report.freeze.json \
  --candidate-freeze /path/to/candidate-snapshot.freeze.json \
  --candidate-snapshot /path/to/translation-snapshot.json \
  --candidate-records-dir /path/to/translation-records \
  --repository-root . \
  --output /path/to/HRC-1.qualification-result.json
```

`qualify-report` independently replays both frozen inputs in its own execution
path, checks the report's public authority and commitment bindings against the
code-pinned manifest, and only then loads controller records. This ordering is
a property of the runner, not proof of what the report producer saw. It exits
`0` only for
`ALL_DECLARED_EXPOSURE_TOKENS_MATCH_CONTROLLER`, `7` for a valid token-set
mismatch, and uses the underlying validation error code for invalid input.
