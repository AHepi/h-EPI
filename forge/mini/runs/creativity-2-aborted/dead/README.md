# Roots that hold a run which never reached its end

Eighteen of them, from CREATIVITY-ARMS-2. Each is a segment that began, wrote a conjecture and
sometimes a reading, and then lost its connection to the model before the run could finish. The
driver sets such a root aside and runs the segment again into a clean one, so every one of these has
a finished twin back in the block.

They are **here rather than beside the finished segments**, and that is the point of the directory.
A records directory is read by enumeration, and a root that is neither a finished record nor an error
naming one is a thing a reader has to know to skip. Nothing knew: `_segments` asked only whether a
log file existed, so the block's own reader counted these as segments. `R.r1` read as **twenty**
segments where sixteen had finished, and both the call count and the row count carried the
difference.

Nothing here was measured, and nothing here should be. They are kept because a run that failed is
still a record of the run failing, and because the count of them is the honest price of an endpoint
that drops connections: eighteen set-aside roots across the twelve cells.
