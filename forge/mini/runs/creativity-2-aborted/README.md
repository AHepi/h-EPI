# The segment that stopped the block, and why it is not in it

`R-r0-s00-unrepaired-reading` is CREATIVITY-ARMS-2's first live segment, run under the plan as it
stood before ERRATA C13 was repaired. It is kept here, outside `creativity-2/`, because it was run
under a different plan from every segment of the block and comparing it with them would be comparing
two machines.

The conjecture was good: it named `records.recover_json_object`, quoted the rule, gave both reply
texts in full and said which answer the rule requires for each. The **reading** then returned
`kernel` and `expect` and none of the three texts, so the executor had nothing to run and recorded
the claim `unrunnable` — which reads as the executor refusing something rather than as an empty
reply.

`ALM-TRANSLATOR-DROPPED-THE-TEXTS` did not exist yet. `ALM-LOOP-STARVED` fired instead, the arm
stopped after four model calls, and reading back through block 1 found the same mode in **9 of 39**
readings there.

So this record is evidence of two things: the failure mode, and the alarms doing the job they were
added for. Four calls, not five hundred.
