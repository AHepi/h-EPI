# The round that found the source had no addresses

Thirty-four finished segments of CREATIVITY-ARMS-2's repeat 0, run before ERRATA C14 was repaired
and set aside rather than counted, because the source a seat is shown is part of what the seat is
shown and a block must run under one plan.

## Why it stopped

Arm `A` proposed `_grounding_kernel` in three consecutive segments, under three different module
paths, and every one was unrunnable. The driver's starvation streak stopped the arm at segment 3.

The reason is not the model. `_grounding_kernel` **exists** — in `creib.forge.mini.conformance_kernels`,
which is mini's own wrapper and not a module of the harness under test. The source seat showed its
body beside seven functions of `creib.forge.conformance.oracle`, with **no addresses on any of
them**, while the brief said to name a function in one of fifteen `creib.forge.conformance.*`
modules. The seat had to guess where each body lived, and it guessed.

Arm `A`'s own critic diagnosed it exactly: *"the executor returned unrunnable with
'MINI_OPEN_KERNEL_NOT_FOUND: records has no _grounding_kernel', but the source shown defines
`_grounding_kernel`; so the run bound the wrong module or failed to load the source. This is a
defect in the run, not in the conjecture or reading."* It then committed `cannot-tell`, so the
attack never landed — which is itself a measurement about the critic, and not one this round is
powered to make.

five were `_grounding_kernel`. The model wrote each of the two under both `oracle.` and `records.`,

where relocation could not save it.

**These numbers are not the block's.** They are one repeat, unfinished, under a superseded plan, and
they are here so that what the repair changed can be seen rather than asserted.
