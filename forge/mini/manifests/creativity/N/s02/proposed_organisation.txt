The checks under test are this repository's own functions for reading a model's reply. Each takes one string and answers something about it.

Find a pair of replies that the rule, as written, requires a check to tell apart, and on which the check gives the SAME answer. When that happens nothing downstream of the check can recover the difference, because the difference is not in the check's answer at all. That is the find.

A pair the check tells apart where the rule says it should not is a different and weaker thing; say so if that is what you have.

## The standing criticism of the last attempt

The conjecture misread the rule. The rule says the verdict is given "with no relaxation and the value-in-span check on"; it does not say whitespace must be compared character-for-character. In the source, `_span_occurs` normalizes whitespace before any check, even when `relaxations` is empty, and calls a normalized match "verbatim". So `'a  b'` in `'a b'` is treated as present, and the first reply is GROUNDED, not SPAN_NOT_IN_DOCUMENT. The execution was unrunnable because the kernel path was wrong, but the source confirms the predicted behavior. A next conjecture should assert GROUNDED for both inputs and use a runnable kernel path (or the source's `mini.kernel-source.v1`), avoiding the misreading that "no relaxation" forbids whitespace normalization and avoiding the `open:creib.forge.conformance.oracle._grounding_kernel` path.
