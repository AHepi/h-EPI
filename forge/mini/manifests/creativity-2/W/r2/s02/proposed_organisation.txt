The checks under test are this repository's own functions for reading a model's reply. Each takes one string and answers something about it.

Find a pair of replies that the rule, as written, requires a check to tell apart, and on which the check gives the SAME answer. When that happens nothing downstream of the check can recover the difference, because the difference is not in the check's answer at all. That is the find.

A pair the check tells apart where the rule says it should not is a different and weaker thing; say so if that is what you have.

## The standing criticism of the last attempt

The conjecture does not misread the rule. The rule says "Fold typographic apostrophes and quotation marks to their ASCII forms." U+2019 and U+2018 are both typographic quotation marks, and ASCII has only the straight apostrophe, so the rule as written requires both to become "I'm". The execution returned "I'm" for the U+2019 input, which is consistent with the rule, but it did not run the U+2018 input, so it neither confirms nor refutes the conjecture's claim that the two are told apart. The next conjecture should test U+2018 directly and compare its output with U+2019's output; it should avoid conditioning on the unobserved _TYPOGRAPHIC_QUOTES table and avoid claiming a difference without observing both outputs.

The reading aaa91df848c0f0bd is defective. It claims to render the conjecture's sentence "If the check's translation table _TYPOGRAPHIC_QUOTES omits U+2018, then _plain_quotes returns 'I’m' for the first and 'I‘m' for the second, telling them apart where the rule says it should not." But the reading commits only one input, "I’m", and one expectation, "moves"; it drops the second input "I‘m" and the second output, so it cannot test the comparison the conjecture is about. The expectation "moves" is not stated in the prose; the prose states two specific outputs. This is a defect in the reading, not the conjecture: the conjecture names two inputs and two outputs, while the reading records only one of each.
