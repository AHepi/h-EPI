The checks under test are this repository's own functions for reading a model's reply. Each takes one string and answers something about it.

Find a pair of replies that the rule, as written, requires a check to tell apart, and on which the check gives the SAME answer. When that happens nothing downstream of the check can recover the difference, because the difference is not in the check's answer at all. That is the find.

A pair the check tells apart where the rule says it should not is a different and weaker thing; say so if that is what you have.

## The standing criticism of the last attempt

The conjecture does not misread the rule; the rule as written and the code part company. The rule says "Every top-level balanced object in the text is a candidate" and "an object nested inside another is not a candidate of its own." For [{"a": 1}], the object is nested inside an array, so it is not a top-level candidate; the function should raise RecordError. The code's top-level scan starts a raw_decode at every '{' without checking whether that brace is inside an array, so it recovers the nested object and returns ({"a": 1}, ()). A next conjecture should try a text where an object is nested inside an array but also has a later top-level object, to see whether the code picks the nested one or the top-level one; it should avoid repeating the claim that the function raises RecordError on [{"a": 1}] alone, since the code demonstrably does not.
