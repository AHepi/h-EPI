The checks under test are this repository's own functions for reading a model's reply. Each takes one string and answers something about it.

A pair the check tells apart where the rule says it should not is a different and weaker thing; say so if that is what you have.

## The standing criticism of the last attempt

Attack on reading e76076fe8be92867: the conjecture says 'gives the same answer on the following two replies' and 'returns {"b":2} for both', but the reading commits expect 'moves', which is an expectation the prose did not state. That is a defect in the reading, not the conjecture. Separately, the conjecture misreads the rule: the rule says 'The object scored is the last one inside a code fence when any fence holds one, else the last top-level object in the text.' The conjecture treats any object inside a JavaScript fence as a fenced object, but the code's fenced pool is the fenced content itself; for ```javascript\n{\"a\":1}\n``` the fenced content is 'javascript\n{\"a\":1}\n', which is not a JSON object, so no fence 'holds one' in the implemented sense. The conjecture also misstates the regex: _FENCE does match the JavaScript fence (the optional json/JSON and \s* allow it), but the captured candidate fails to parse. A next conjecture should avoid claiming the JavaScript fence is not collected and should instead test a fence whose entire content is a JSON object, or clarify the rule's 'holds one' as fenced content being an object.
